# AGENTS.md — правила проекта man-vs-pc

## Назначение
Проект: **Human vs Computer** — «Человек против Компьютера». Английское имя репозитория: `man-vs-pc`.

## Основные правила
- `_/` — системная директория документации, заданий, планирования и управления. **Не включать в сборку и пользовательский интерфейс приложения; не импортировать её содержимое в runtime.**
- Общие задания и материалы размещать по датам: `_/tsk/MM-DD/`. Задания для конкретных мини-игр хранить в `_/tsk/games/{slug}/MMDD/` (например, `_/tsk/games/coin-toss/1015/`). Название папки игры — английский slug **без номера**, а числовой ID сохраняется в файлах. Не смешивать разные даты.
- Для каждой игры хранить `game.md` (краткая игровая механика и интеграция) и `sprite.md` (перечень A–E и готовый промпт генерации). Навигация: `_/tsk/games/README.md`.
- Референс и вёрстка — **первый этап**. Держать макеты/прототип отдельно от рабочих компонентов приложения. Только после утверждения дизайна переносить решения в код приложения.
- Источник требований: `_/tsk/10-14/01-original-notes.md` и `02-structured-draft.md`. Актуальные уточнения и поручения: `_/tsk/10-15/`; при противоречиях приоритет у более новых требований.
- Не изобретать сложные игровые правила раньше отдельного согласования. Подготовить платформу, экраны, интеграционный контракт и демонстрационные состояния.
- 20 мини-игр, 30 спрайтовых персонажей (слот 0 — компьютер), единые схемы спрайтов игр.
- Для людей использовать круглую подложку под прозрачным изображением персонажа. Компьютер отображается без круга.
- На главной показывать **всех активных участников VS Компьютер**, общий счёт «Люди — Компьютер» и цель соревнования (по умолчанию **10 общих побед**). Это отдельный счёт от личного матча (по умолчанию **до 2 побед**). **Одна победа в завершённом личном матче = одна победа в общем счёте**; не суммировать раунды как общие победы. При исчерпании очереди без достижения цели начинать новый круг, сохраняя общий счёт.
- Состояния соревнования и статистику сохранять в `localStorage`. **Каждую ничью** показывать отдельным исходом и сохранять в истории со своим счётчиком (матч, сессия, всё время); ничьи не засчитывать как победы ни для личного матча, ни для общего соревнования. Предусмотреть безопасную обработку повреждённых/устаревших данных и версионирование формата.
- Случайный выбор должен быть честным. Компьютер в мини-играх не должен читать скрытый выбор игрока до фиксации своего хода.
- При изменениях не перезаписывать чужую работу без проверки, не трогать папку `_/` как часть интерфейса.
- Доступность для интерактивной доски: крупные элементы управления, читаемость на 16:9, действия мышью/касанием; не полагаться на hover.

## Порядок работы Cursor
1. Ознакомиться с README и заданиями в текущей папке `_/tsk/MM-DD/`.
2. Проверить существующие файлы и принятые технические решения; использовать имеющийся стек, если он уже есть.
3. Реализовать задачи по этапам, не смешивая прототип дизайна и готовые мини-игры.
4. Описывать сделанное и способ локального запуска; не объявлять неготовые механики работающими.

## Минимальный критерий завершения очередного этапа
Вёрстка экранов доступна для просмотра; есть навигация демонстрационного сценария, placeholder-графика и пример импорта JSON. Игры не выдаются за реализованные, пока их правила и логика не определены.
