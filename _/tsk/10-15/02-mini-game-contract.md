# Cursor — универсальный промпт для одной мини-игры

Когда правила конкретной мини-игры будут утверждены, используй этот промпт вместе с ними.

> Реализуй мини-игру **[ID / название]** по приложенным правилам в уже существующем `man-vs-pc`. Не создавай отдельное приложение. Используй общий экран игры, дизайн, аватары, спрайт этой игры, настройку «до N побед», статистику и переходы проекта.
>
> Предусмотри состояния: **ожидание → старт → ход человека / ход компьютера → проверка результата → победа / поражение / ничья → следующий раунд**. Компьютер должен быть реальным игровым соперником: фиксировать свой скрытый выбор до раскрытия человеческого, не подсматривать ответ и не подменять результат. Честно показывай, если компьютер действует случайно или использует заданную модель реакции.
>
> Мини-игра сообщает общему приложению только свой результат: **human / computer / draw**, а также ID игры, основные показатели (если есть) и время раунда. Счёт матча, ачивки и `localStorage` ведёт общая оболочка, а не каждая мини-игра отдельно.
>
> Обеспечь повтор раунда, безопасный выход, сброс таймеров и обработчиков, работу мышью/касанием, крупные элементы, короткие визуальные правила. Не ломай сценарий выбора игрока и следующего участника.
>
> Проверка: выигрыш человека, выигрыш компьютера, ничья, завершение матча при N победах, возвращение в меню и повторный запуск.

## Минимальный интерфейс интеграции (ориентир, не навязывая стек)

- Вход: `gameId`, текущий участник, параметры игры/сложности при наличии, `onFinish(result)`, `onExit()`.
- `result.winner`: `"human" | "computer" | "draw"`.
- Остальные показатели — опциональны, только действительно полученные внутри игры.
- Не дублировать сохранение статистики в самой игре.
- Загружать графику по единой карте спрайтов из `04-game-sprite-catalog.md`.

**Сейчас не реализовывать механики 20 игр.** Этот шаблон применяется по одной мини-игре после согласования её правил.
